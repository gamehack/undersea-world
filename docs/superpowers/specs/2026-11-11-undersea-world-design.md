## 1. 项目使命与机会

**一句话定义：** 让用户在手机或电脑浏览器里随时进入一个遵循基本海洋生态规律的虚拟海底世界，自由潜游、观察海洋生命并安静停留。

现实中的潜水、远距离海洋旅行和近距离观察海洋生命受到地点、时间、费用、身体条件等约束。本项目提供随时进入、低成本且没有潜水危险的**数字体验**，不是对实体潜水的身体感受或真实生态观察的完全替代。

此项目与「摸鱼山」「云猫岛」「听雨小屋」同属数字休闲空间探索，但保持独立产品边界。可以逐步复用通用的音频、性能检测、输入适配、分析事件与部署组件，不在 MVP 阶段合并成统一大型平台。

## 3. 用户与核心场景

### 3.1 目标人群

1. 喜欢海洋、鱼类、珊瑚、海龟等海洋生命，但无法经常亲临海洋的人。
2. 在工作或学习间隙，想有 3—10 分钟低压力视觉休息的人。
3. 对潜水感兴趣，但暂时受费用、地点、时间或身体条件限制的人。

首版不主打专业潜水训练，不要求潜水知识，也不以生物科普考试为目的。对于低龄用户，界面应保持简单；但本阶段不宣称具备专门的儿童适龄认证。

### 3.2 典型使用路径

1. 通过网页链接进入，看到静态首屏与「进入海底」按钮。
2. 点击后初始化轻量场景；音频默认静音并提供明确开启按钮，避免移动端自动播放失败。
3. 首次显示 10 秒以内可跳过的输入提示：PC 使用键鼠、手机使用双虚拟控制区；随后进入生态区。
4. 自由转向、前进、上浮和下潜，近距离观察鱼群、海龟、珊瑚及光影。
5. 松开控制后缓慢减速停留；可隐藏 UI、打开/关闭声音、改变画质、返回入口。
6. 随时离开，无惩罚、无进度损失、无弹窗索取签到。

### 3.3 用户价值与反面设计

- **要做到：** 不用安装、容易进入；有探索自由；海洋生命像在自主生活；沉浸、平静、没有压力。
- **不要做到：** 用户被路线指示、强制教学、金币、任务、交互弹窗、密集菜单或广告打断。
- **不声称：** 可以代替真实海洋环境、专业潜水、生态研究，或具有医疗治愈效果。

## 5. 首版世界与生态设计

### 5.1 场景组织

建议构造一个**可连续探索的热带浅海珊瑚礁区域**。空间尺度为视觉/交互设计参数，并非真实 GPS 地图；建议初版有效探索范围约 60m × 60m、水深约 3—18m，需由素材与手机性能验证后调整。

地貌划分为四个相连小区：

1. **入水浅滩**：光照明亮、水色透明，适合第一次进入和学习控制。
2. **珊瑚观赏区**：以健康珊瑚、岩石、小鱼群为中心的视觉主体。
3. **礁石通道**：有适度遮挡和转角，形成真实的探索感。
4. **开阔缓坡**：可以看到更远的海水景深与海龟巡游路径，作为安静停留点。

世界边界不能以突兀无形墙呈现。接近边界时通过海流缓慢引导回主区、远景海底延伸及柔和转向控制；不得出现无限上浮进入空白天空或穿过海床。

### 5.2 生物行为规格

| 物种组 | 初版规模建议 | 行为规则 | 约束 |
|---|---:|---|---|
| 小型礁鱼 A | 10—20 个体 | 群游、转向、间距维持、局部游弋 | 活动范围贴近礁区 |
| 小型礁鱼 B | 6—12 个体 | 小群穿梭珊瑚外缘、随机停顿 | 不与岩石/珊瑚穿模 |
| 独游礁鱼 | 3—6 个体 | 低速巡游、觅食式停顿 | 不形成不合理大群 |
| 海龟 | 1 个体，必要时增加至 2 | 长路径巡游、缓慢转向、摆鳍、间歇上浮 | 不持续高速旋转，不停滞抖动 |

技术层分成 `SpeciesProfile`（视觉/生态配置）、`BehaviorState`（状态机）、`Steering`（趋向/避让）、`Animation`（摆尾摆鳍），支持替换模型，不把行为写死在单一模型上。

基础鱼群只实现轻量的分离、对齐、聚合与预定义兴趣点，不要求高成本流体/群智能仿真。每帧使用固定预算更新部分个体；远处个体降低更新频率。海龟按空间曲线与状态机行走，同时提供物理合理的速度/转弯上限。

生态真实性：每个资产必须记录名称、参考物种或「泛化鱼类」标签、适宜环境、模型/贴图授权来源。无法确认的鱼类模型不以具体科学物种命名。

### 5.3 视觉与声音基调

- 美术：首版执行**轻量生态写实 B**；物种轮廓、比例、行为和水色真实可信，允许明显但不粗糙的实时 3D 质感，不以照片级渲染为验收标准。避免霓虹发光珊瑚、幻想巨兽与过饱和色彩。
- 画面：水体蓝绿色渐变、距离雾化、温和散射光，低端设备使用简化效果。
- 动作：全部采用缓慢、连续、平滑过渡，避免突发镜头晃动和频繁闪烁。
- 声音：海水环境氛围声与轻微气泡声；不以声称「水下真实声场」方式包装普通环境素材。
- UI：仅必要控制、音量、画质、帮助、退出与性能提示；默认可自动隐藏。

## 6. 操作与交互规范

### 6.1 PC

- 鼠标拖动/指针锁定：改变视角；首版优先拖动视角，用户主动选择后才锁定指针。
- `WASD`：沿水平视线方向游动；`Space`：上浮；`Shift` 或 `C`：下潜。
- `Esc`：释放指针/暂停输入并显示菜单。
- 松手采用柔和阻尼；镜头默认无头部摇晃、无快速滚转。

### 6.2 手机

- 左下虚拟摇杆控制平面方向，右侧拖动视角；右侧浮/潜按钮控制垂直移动。
- 控件可按横/竖屏重排，避免手指遮挡核心生物观赏区。
- 首次进入提供短提示，随后可在帮助中再次查看。
- 页面切至后台或失焦立即暂停动画循环和音频；恢复时重新检查渲染上下文。

### 6.3 舒适度与可访问性

- 提供「缓慢模式」、音效开关、减少粒子/光束、关闭自动相机运动。
- 尊重系统减少动态效果偏好；允许暂停所有自发镜头运动（海洋生物动画可继续）。
- 菜单支持键盘 Tab 和可见焦点；按钮标识、对比度、触摸热区应可用。
- 首版不应通过鼠标/触摸操作阻止浏览器基本退出和返回能力。

## 7. 前端技术架构

**推荐技术组成：** TypeScript + Vite + Three.js（固定发布版本）+ WebGL 2；静态编译输出部署 Cloudflare Pages。首版无服务端运行时、无数据库、无外部 AI 推理依赖。

```text
Web App
├─ App shell / Loading / Settings / Analytics
├─ Input adapters (keyboard, pointer, touch)
├─ Experience controller (enter, pause, resume, exit)
└─ Three.js scene
   ├─ World / Terrain / Reef props
   ├─ Water atmosphere / Lighting / Particles
   ├─ Camera / Navigation / Collision
   ├─ Creatures / Species / Schooling / Animation
   └─ Quality controller / Resource manager

Static hosting: Cloudflare Pages
Assets: optimized GLB/glTF + compressed textures + audio
```

### 7.1 关键模块接口（实施时定型）

- `ExperienceController`: `load()`, `enter()`, `pause()`, `resume()`, `dispose()`。
- `NavigationController`: 统一 `moveX/moveY/moveZ/lookX/lookY` 输入，不耦合设备。
- `SceneWorld`: 加载区域、维护边界与碰撞代理、管理场景资源。
- `MarineLifeSystem`: 生物创建、分层更新、池化、停用/恢复。
- `QualityManager`: `low/medium/high/auto`；控制分辨率、绘制距离、粒子与阴影。
- `Telemetry`: 受控匿名事件接口，失败不得阻断体验。

### 7.2 资产管线

- 优先从明确可商用、可再分发或自制来源获取低多边形但视觉真实的模型；记录资产名称、作者、许可、来源链接、修改记录。
- 使用 glTF/GLB，必要时使用几何压缩和 KTX2/Basis 纹理压缩；压缩收益和解码成本通过真实设备测量。
- 每类鱼重用几何和材质，尽量实例化；不同物种使用差异化轮廓/动画而不靠纯贴图换色。
- `assets/manifest.json` 或同等清单记录来源许可、体积、LOD 级别；CI 检查缺失引用和单资源体积。
- 优先从静态资源交付；Cloudflare Pages 单个静态资源目前最大 25 MiB，设计时应保持单项显著低于此限制（以部署时官方限制为准）。

### 7.3 容错与生命周期

- 初次加载失败：显式重试和返回静态预览；失败不无限旋转加载动画。
- WebGL 2 不可用：显示可理解的原因和静态海洋预览，避免空白页。
- `webglcontextlost`：暂停渲染并提示；恢复时重建必要资源，失败可刷新。
- 进入后台：暂停渲染与行为更新；返回时使用时间上限避免大幅模拟跳跃。
- 路由退出/卸载：释放纹理、几何、材质、事件监听和声音资源。

## 8. 性能预算与测试策略

以下为**设计目标，不是已经达到的实测结果**：

| 指标 | 手机目标 | PC 目标 | 检查方式 |
|---|---|---|---|
| 首次可交互 | 4G/常规网络下尽量 ≤ 8 秒 | 常规宽带下尽量 ≤ 5 秒 | 实机网络节流 P75 |
| 初次必需下载 | 尽量 ≤ 8 MiB（压缩传输） | 尽量 ≤ 12 MiB | 构建产物体积检查 |
| 平均帧率 | 中档机尽量 ≥ 30 FPS | 常规独显/核显尽量 ≥ 45 FPS | 10 分钟场景巡游 |
| 长时间运行 | 10 分钟不崩溃、无持续内存增长趋势 | 同左 | 运行日志及内存曲线 |
| 同时可见生物 | 基于性能预算动态调整 | 同左 | 自动场景压力测试 |

测试设备矩阵至少覆盖：Android Chrome 中档手机、iPhone Safari、iPhone Chrome（同 WebKit 内核限制）、Windows Chrome、macOS Chrome/Safari；若缺实际设备，先用模拟工具筛查并在上线前安排真实手机抽测。不得仅凭桌面开发机的 FPS 宣称移动端通过。

**降级顺序：** 降渲染分辨率 → 减粒子/光束 → 缩短视距与植被细节 → 降生物更新频率与数量 → 使用更简单材质；最后才影响可游动范围。画质自动调整必须有用户手动覆盖。

## 9. 事件埋点与上线后验证

### 9.1 事件方案

| 事件 | 意义 | 必需字段 |
|---|---|---|
| `app_opened` | 页面访问 | device_class, referrer_group |
| `scene_load_started` | 开始加载 | quality_tier |
| `scene_load_succeeded` | 成功进入 | load_duration_ms, quality_tier |
| `scene_load_failed` | 加载失败 | error_category, stage |
| `experience_started` | 实际开始潜游 | input_type |
| `experience_3min` | 持续体验至少三分钟 | active_seconds |
| `experience_10min` | 持续体验至少十分钟 | active_seconds |
| `experience_ended` | 离开 | active_seconds, total_seconds |
| `quality_changed` | 画质调整 | from, to, reason |
| `render_recovered` | 上下文故障恢复 | cause, success |

`active_seconds` 只统计可见且用户未暂停的时段；事件不得重复触发。首版优先接入用户已熟悉的站点分析体系，但必须遵守适用的同意/隐私规则；不上传精确坐标、操作轨迹全文、设备硬件唯一标识。

### 9.2 首轮验证假设

上线后观察 14 天（低流量时只作方向性判断）：

- 进入成功率是否达到至少 95%（需排除机器人流量及已知无法使用 WebGL 2 的设备）。
- 实际开始体验的访客中，有多少达到 3 分钟、10 分钟。
- 手机/PC 的加载失败和帧率问题是否显著影响停留。
- 用户是否主动二次访问；匿名统计无法可靠识别同一人的情况下，不伪造留存数据。

所有百分比阈值为初步目标，先观察基线，再决定迭代方向。不因小样本数据而做过度结论。

## 10. 分阶段交付与验收

### M0｜设计确认（当前）

- 审批本设计文档和首期边界。
- 定项目仓库/域名（可暂缓域名，不阻止开发）。
- 明确许可合规的 3D 资产来源。

### M1｜技术骨架与导航

- 静态站点、场景加载、WebGL 能力探测、键鼠/触控、相机/碰撞、三档画质。

### M2｜海洋生态与表现

- 地形、珊瑚、雾、水下光照、鱼群与海龟行为、声音和资源优化。
- 验收：生态行为不明显穿模/抖动，背景/恢复稳定，声音可控。

## 13. 技术路线比较及决策理由

| 路线 | 效果 | 主要优势 | 关键代价 | 决策 |
|---|---|---|---|---|
| 方案 1：360° 全景/预设视点 | 可观景，有限移动 | 开发和运行成本较低 | 不能真正自由潜游 | 未选 |
| **方案 2：Three.js + WebGL 2 实时 3D** | 连续移动、动态鱼群与场景 | 满足核心体验、可渐进优化 | 需 3D 资产管线与移动端性能优化 | **已选** |
| 方案 3：高精度实时 3D | 画面上限高 | 更强视觉上限 | 资源大、低端手机可用性差、制作周期长 | 未选 |

本项目以浏览器访问、免费优先、移动端性能和真实自由探索为核心约束。方案 2 在沉浸程度与成本之间最适合；未来可在不改变产品定位的情况下逐步提高画面精度。选择 WebGL 2 不是承诺所有旧设备都能运行，因此必须有能力检测和静态兜底。

## 14. 风险、缓解与待决事项

| 风险 | 后果 | 缓解方式 |
|---|---|---|
| 模型和贴图许可不明 | 无法安全公开商用 | 使用可验证许可的资产，清单留证 |
| 手机 GPU 差异大 | 黑屏、掉帧和发热 | 设备探测、画质分档、性能抽测、兜底 |
| 追求真实导致场景过重 | 长时间加载、体验流失 | 优先一处生态区、LOD/压缩/实例化 |
| 动作/镜头导致晕动症 | 用户不适 | 缓慢模式、禁自动晃动、可随时暂停 |
| 美术生态失真 | 破坏真实模拟定位 | 物种栖息地与行为规则检查 |
| 数据少/样本偏差 | 错误商业判断 | 上线后先采集基线，不设过早商业结论 |

**交由实施者在不改变用户体验方向的前提下决定：** 工程目录、状态管理具体实现、建模工具、鱼群算法参数、场景坐标系、Vite/Three.js 具体锁定版本、测试框架和 CI 配置。

**视觉标准已决：** 采用 B「轻量生态写实」，不追求照片级渲染；在真实可信与手机流畅之间，以可用性优先。美术资产与效果分级以这一标准验收。

**需要创始人确认的运营决策（后续，不阻断设计批准）：** 正式中文/英文产品名、GitHub 仓库归属与可见性、公开域名、正式上线与商业化时间。若实现阶段缺少可合法使用的高质量海洋资产，需在「先自制简化资产」与「购买资产」之间重新决策，默认优先合法免费方案。
